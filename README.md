# 402 Vision Studios · Studio

Generation studio for 402 Vision Studios. Write a brief or pick one of the
production presets (product spot, vertical reel, editorial portrait, campaign
key visual, event aftermovie, brand still life), choose a model and generate
images or video through the [Higgsfield platform API](https://api.higgsfield.ai).

Built on the Higgsfield Studio template (`higgsfield-ai/app-templates/studio`)
with Next.js 16, Tailwind v4 and shadcn/Base UI. Read `AGENTS.md`,
`layouts/AGENTS.md` and `components/studio/AGENTS.md` before changing the app.

## Run it

```sh
pnpm install
pnpm dev            # http://localhost:3000
```

1. Click **Connect API key** in the sidebar.
2. Paste the complete key copied from
   [open.higgsfield.ai/api-keys](https://open.higgsfield.ai/api-keys), as-is.
3. Pick a preset or write a prompt, then **Generate**. **Cancel** sends a real
   cancel request to Higgsfield (only queued requests can be canceled).

The key is stored in an HTTP-only cookie by a server action and is only used by
the server (`Authorization: Key <api-key>`). It is never put in localStorage,
client bundles, server-action responses or logs. **API key saved** means the
cookie is set, not that Higgsfield accepted the key; the first request tells
you that.

## Environment

| Variable | Where | Value |
|---|---|---|
| `HF_API_BASE_URL` | server only (`.env.local`) | `https://api.higgsfield.ai` |

No other secrets are needed: users bring their own key, and reference uploads
use a signed URL issued with that same key. See `.env.example`.

## How generation works

- `generation/actions.ts` — server actions. Submits are validated against the
  selected model's schema, carry a per-click submission id and are
  de-duplicated server-side (`generation/submissions.ts`), so a double click or
  replayed action never pays twice. A submit POST is never retried; a timeout
  is reported as "unconfirmed".
- Actions return typed results (`generation/errors.ts`) instead of throwing, so
  missing key, rejected key (401/403), rate limits (429), validation errors and
  outages reach the UI in production too. A missing or rejected key reopens the
  key dialog.
- `generation/poll.ts` — one batched status call per interval for every run in
  flight, exponential backoff (4 s → 30 s) on rate limits or outages, and
  terminal handling for `completed`, `failed`, `nsfw` and `canceled`. Failed and
  canceled runs stay in the feed.
- `app/api/upload/route.ts` — requests a signed upload URL; the browser PUTs the
  file with every returned header and no credentials, and records `public_url`
  only after the PUT succeeds.

History and projects are browser-local (IndexedDB). Each browser uses its own
key, so there is no shared request ownership to enforce. If you switch to a
shared server key (`HF_API_KEY`), store each `request_id` with its user and
check ownership in the status and cancel actions first.

## Models

All 28 model files in `generation/catalog/models/` (38 picker entries: 30 video,
8 image) are installed and shown. `generation/catalog/models.generated.ts` is
generated by `scripts/sync-models.mjs` on every dev/build; do not edit it.
